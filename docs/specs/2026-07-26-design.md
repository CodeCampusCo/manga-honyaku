# manga-honyaku — Design

Status: draft, pre-implementation
Date: 2026-07-26

## What this is

A manga translation workflow where an LLM agent reads the pages and a small amount
of Python does the mechanical work. The agent is not called through an API to
translate a bubble at a time; it reads the whole page, works out what is happening,
and writes its results into a per-page file. Python then renders those results back
onto the artwork.

Primary language pair is Japanese → Thai, but nothing below is specific to Thai
except the shaping and line-breaking notes.

## Why the work is split this way

Bubble-at-a-time translation loses information that is only visible at page level.
Three cases, all observed on real pages during design:

1. **One sentence spans several bubbles, sometimes across a panel break.**
   Japanese puts the verb last; Thai does not. Translating each bubble in isolation
   produces fragments that do not join, and repeats the sentence-final politeness
   particle in every fragment instead of once at the end.

2. **Thai forces distinctions Japanese leaves open.** `はい` carries no gender and no
   politeness level. Thai must choose `ครับ` / `ค่ะ` / bare. That choice comes from
   who is speaking to whom and their relative status — page-level information.

3. **Story-bearing text is often not in a bubble at all.** Signs, phone screens,
   handwritten notes, printed flyers. The detector does not see text baked into
   artwork, and some pages carry their most important beat entirely in such text.

Conversely, the parts that are genuinely mechanical — finding boxes, removing the
old text, fitting new text inside a bubble's curve — are done far better and far
cheaper by code than by an agent.

## Division of labour

| Done by code | Done by the agent |
| --- | --- |
| Detect text regions, return coordinates | Decide reading order |
| OCR the Japanese | Attribute each line to a speaker and addressee |
| Draw numbered boxes on a copy for review | Give each region a role: dialogue / sfx / title |
| Remove text, produce bubble masks | Group regions into utterances |
| Fit and render the translation | Translate, then split back across bubbles |
| — | Find story-bearing text the detector missed |
| — | Maintain the series context files |

The agent never touches pixels; it reads images and writes JSON. Code never makes a
judgement about meaning.

## Directory layout

```
<series>/
  raw/        source pages, read-only, never written to
  work/       derived per-page artifacts
  series/     accumulated context for this series
  out/        rendered pages
```

`raw/` is read-only without exception. Every stage writes elsewhere. The reason is
practical rather than defensive: the loop of adjusting a translation, a font, or a
box and re-rendering is run many times, and a single stage that wrote back to `raw/`
would destroy the only copy that cannot be regenerated.

### Per-page artifacts

```
work/<page>.detector.json   what the detector found
work/<page>.agent.json      the working file: roles, order, speakers, translations
work/<page>.boxes.png       the region ids drawn on a copy, for the agent to read
work/<page>.clean.png       artwork with the original text removed
work/<page>.masks.png       bubble interiors, 8-bit, pixel value = region index
```

Both JSON names say who wrote them. An unmarked `<page>.json` read as the page's
one file when it is in fact the disposable half.

The pipeline runs one way. Each stage reads the artifact before it and writes the
one after, and nothing reads backwards: `clean` and `render` never open
`<page>.detector.json`, and no stage but `prepare` writes `<page>.agent.json`.

**Only the working file cannot be rebuilt.** Detection costs a second a page.
The reading is the work of understanding the page, and nothing else holds a copy
of it — so `detect` may overwrite its own output freely, while `prepare` refuses
to overwrite a working file that already exists.

`prepare` rewrites the detector's regions into the working file, and from there
the file is the agent's. The agent drops the regions it will not act on, adds the
ones the detector never saw, and accumulates the source and the translation. What
it drops stays visible in `<page>.detector.json`, which nothing reads after
`prepare` but which remains the record of what the detector saw.

**Ids are not renumbered when regions are dropped.** `B5` removed leaves
`B4, B6, B7`. The agent reads those ids off `<page>.boxes.png`, and renumbering
would put the image and the file out of step with nothing to signal it.

To change detection after a page has been read, start again from raw. There is no
merge; a half-updated working file would be worse than either version of it.

The masks file exists because the renderer needs more than a bounding box. It
computes a safe area inside the bubble with a distance transform so that text
follows the bubble's actual curve and never touches the outline. Without a mask it
falls back to a padded rectangle, which overflows on round and irregular bubbles.

## Pipeline

```
raw/<page>.jpg
      |
      v
  [detect]  RT-DETR -> boxes + placement              -> work/<page>.detector.json
      |
      v
  [annotate]  numbered boxes drawn on a copy               -> work/<page>.boxes.png
      |
      v
  [prepare]  regions rewritten, OCR run over them     -> work/<page>.agent.json
      |
      v
  ( agent reads raw page + boxes page + series/, and edits the working file:
    drops what it will not act on, adds what the detector missed, writes
    order, role, speaker, utterances, translation )
      |
      v
  [clean]  remove text                        -> work/<page>.clean.png + .masks.png
      |
      v
  [render]  fit and draw the translation                   -> out/<page>.png
```

Stages are separate commands, not one pass. Re-running `render` after editing a
translation must not re-run detection or OCR.

`annotate` draws the region id outside the box, never inside it. Drawn inside, the
label covers the first character of the text it exists to make readable — an error
with nothing to signal it, since the agent then confidently reads the truncated
text.

Region ids use distinct prefixes per placement (`B` for in-bubble, `F` for
free-floating, and a prefix of its own for a region the agent added). Deriving the
prefix from the detector's own label would give `text_bubble` and `text_free` the
same letter and produce colliding ids.

## The working file

```jsonc
{
  "version": 1,
  "page": "0070.jpg",
  "img_width": 1132,
  "img_height": 1600,

  "regions": [
    {
      "id": "B1",
      "box": [530, 180, 610, 330],
      "bubble": [515, 165, 625, 350],    // the outline it sits in
      "placement": "bubble",             // the detector: where the text sits
      "score": 0.964,
      "role": "dialogue",                // the agent: what the text is for
      "vertical": true,
      "source": "はい マネージャーさんから連絡があって",
      "utterance": "u2",
      "order": 2,
      "speaker": "sakura",
      "addressee": ["shinobu", "masaki"],
      "target": "ค่ะ คุณผู้จัดการติดต่อมา",
      "weight": "bold",                  // optional; regular unless said
      "scale": 1.0,                      // optional; size against the original
      "status": "ok"
    },
    {
      "id": "A1",                        // the agent found this one
      "box": [640, 900, 980, 1180],
      "placement": "free",
      "role": "image_text",
      "source": "水着フェス プール撮影会",
      "target": null,
      "note": "already stated in the dialogue; no information lost"
    }
  ],

  "questions": [
    "B2 — speaker unknown; off-panel voice over an establishing shot. Does not affect the Thai."
  ]
}
```

Notes on the schema:

- **`placement` and `role` are separate axes, not two answers to one question.**
  `placement` is the detector's, and the only thing a detector is in a position to
  say about a piece of text: whether an outline encloses it (`bubble`) or it sits
  loose on the artwork (`free`). `role` is the agent's, and says what the text is
  for. They were `detector_class` and `class`, which shared a word and so read as
  one field with two sources — inviting exactly the collapse that would delete one
  of them, and with it the only way to notice that the two disagree. During design
  the agent overrode the detector twice and was wrong both times; the detector is a
  check on the agent as much as the reverse. No code branches on `placement` —
  `bubble` carries the geometry that `clean` needs — so it is kept purely as
  evidence.

- **`weight` and `scale` are the typography the agent controls.** Lettering size is
  fixed before anything is wrapped, at a constant fraction of the size the Japanese
  was: a box of area A holding n Japanese characters was lettered at about
  sqrt(A/n), and the Thai is set at 0.65 of it. Wherever the original was 40 the
  Thai is 26, on every page. The line breaking then has to make that size work, and
  only a region that cannot hold its line in either its own box or the whole bubble
  comes down — on the first page translated, three of fourteen.

  Fitting the largest size that happens to go in does the opposite: the shape of
  each box sets the size, and text the artist lettered identically comes out
  anywhere across a range of two. `scale` is the escape hatch, for a shout the
  artist drew no larger or a whisper drawn no smaller. `weight` picks a bolder cut
  of the same face. Both absent by default.

  Regions sharing an `utterance` are lettered at one size, the largest all of them
  can hold. One sentence at two sizes reads as two sentences.

- **`utterance` groups the regions that carry one sentence.** The agent translates
  the joined source and splits the result back across them, rather than translating
  each bubble alone — which repeats the sentence-final particle in every fragment and
  drops the connective that joins them. Both happened on the first page translated,
  in the two utterances that span more than one bubble.

  The grouping is a label on the regions and nothing more. It was an array of its own,
  carrying the joined source and target, until the joined target turned out to be
  byte-identical to concatenating the members' — the same text in two places, free to
  drift apart with nothing to catch it. A region in no group carries no label; nine of
  the eleven utterances on that page were a single bubble.

- **A region the agent added has no `placement`,** because nothing found it and
  so nothing classified it. It owns its `box` outright, where a detected region's box
  came from the model. Its id takes a prefix of its own so the two can never collide
  and the origin of a region is readable from its name.

- **Text found in the artwork is a region like any other,** not a separate list. It
  was one at first, which meant two shapes for the same thing and no stage that knew
  what to do with the second. Entries deliberately left untranslated keep their reason;
  blank and missing must stay distinguishable.

- **`questions` records only uncertainty that changes the output.** An unattributed
  line whose Thai needs no gendered particle is not a question — recording it makes
  the file noise. The test is not "how confident am I" but "if I am wrong, does the
  reader see anything different".

- **`detect` writes `score` and a `detector` block** — the confidence per region, and
  the model id, threshold and input size used for the page. Both are provenance for
  a stage whose output is otherwise indistinguishable between a well-tuned run and a
  badly-tuned one. Neither is read by any later stage.

- **`bubble` is resolved once, by `detect`.** The rule is geometric — the smallest
  detected outline whose box encloses the text's centre, since conjoined lobes overlap
  — so the stage that has both lists is the one that should match them. A region then
  describes itself completely and `clean` matches nothing. The three ways the match
  can come out wrong (no outline, one outline holding two regions, an outline holding
  none) are reported by `detect` rather than surfacing two stages later as a bubble
  whose text was quietly left in place.

- **`status: "declined"` is not the same as dropping a region.** A region is dropped
  when nothing about it will ever reach the reader — a sound effect, or something the
  detector saw that is not text. It is declined when it *is* a line that should be
  translated and the agent will not translate it, and then it has to stay in the file
  with its reason, and appear in `questions`. Dropping a declined region would render
  a page that looks complete and is missing a line, which is the one outcome this
  design refuses.

### Region roles

| role | meaning | treatment |
| --- | --- | --- |
| `dialogue` | someone is saying it | translate |
| `sfx` | sound effect | drop; the artwork is not touched |
| `title` | chapter or section heading | translate, separate styling |
| `image_text` | text painted into the artwork | translate; the artwork is not touched |

A region is `dialogue` if it has a bubble outline, regardless of content — a grunt or
a tongue-click inside a bubble is speech. Text without an outline is `sfx` or
`dialogue` depending on whether a character is uttering it, which only the agent can
decide.

There was a fifth role, `dialogue_free`, for speech drawn without a bubble. It was
`dialogue` with `placement: "free"` written as one word, and it disappeared the moment
the two axes were named apart. Over chapter 3 the four combinations that occur are
dialogue/bubble (212), dialogue/free (2), image_text/free (2) and title/free (1).

`image_text` covers a sign, a phone screen, a printed flyer — text that belongs to the
drawing rather than to a speaker. It is translated, because it often carries the beat
of the page, but the drawing is left alone: painting over a door plate damages the
artwork to no purpose. Most of it is not detected at all and the agent adds it; the
role exists because sometimes the detector does find it, as with a door plate reading
倉庫 that fits none of the others.

`placement` does not carry this distinction and cannot be made to. In
testing, one page classified a sound effect and a line of floating speech identically,
and another classified two in-bubble lines as free text. Large stylised sound effects
overlaid on artwork were consistently not detected at all — which happens to be the
desired outcome, since those are exactly the ones that must not be disturbed.

## Series context

```
series/<work>/
  raw.txt              one line: where the scans are
  words.txt            one Thai word per line; the line breaker's dictionary
  lettering.json       the bands that assign a size tag, and what each tag is worth
  glossary.md          names, terms, honorifics, agreed transliterations
  characters.md        who they are, relationships, and how each one speaks
  summary.md           rolling plot summary, fixed length
  questions.md         unresolved items, carried forward
  pages/               <id>.agent.json — the translation, rebuilt by nothing
  build/               <id>.detector.json .boxes.png .clean.png .masks.png
  out/                 <id>.png
```

`characters.md` records speech register, not just identity. Attributing a line by
voice is only possible once a character's voice has been established, so this file is
what makes later volumes cheaper to translate than the first. It also records the
visual invariant used to identify each character — a costume item, an accessory —
because faces, hair and proportions are routinely deformed for emotional effect and
are unreliable as identity evidence.

How an honorific is rendered, what happens to a sound effect inside a bubble, how
a held vowel is spelled — those hold for any manga and live in the skills, not in
a work's own files. A work writes down only where it departs, in `style.md`, and
most works never need the file.

`summary.md` is capped in length and rewritten rather than appended, so that context
size stays constant across a long series.

## Reading rules

These belong in a skill rather than in this document, and accumulate as the work
proceeds. The current set, each derived from an observed error:

1. Identify characters by costume and props before hair or face. Manga deforms
   faces, hair and proportions to convey emotion; clothing stays constant.
2. Never invent a character to account for an unattributed bubble. Needing an unseen
   character is a signal that an identification is wrong, not an explanation.
3. Verify reading order by conversational coherence. If the geometric order yields a
   conversation that does not follow, the order or the attribution is wrong.
4. Establish speaker, addressee and relative status before writing the target line.
5. Translate an untranslatable formula by its function, not its words.
5b. Match the length of the original, not only its sense. The bubble was drawn to
   hold what the Japanese said, and a version that carries the meaning in half the
   words leaves it looking empty. Where the original implies more than a bare
   rendering says — `〜があって` is "it so happens that", `らしい` is "I hear that",
   `けっこう` is "quite, as these things go" — say it in full. This is not licence
   to pad, and a line the artist drew short stays short.
6. Two joined bubbles mean one speaker continuing, possibly across a camera cut —
   bubble shape is grammar.
7. Bubble-tail direction and speech register are independent evidence. When they
   conflict, that conflict is information; do not silently pick one.
8. A bare name or job title in a bubble is a vocative, not a caption.
9. A bubble whose speaker is outside the panel is ordinary manga grammar.
10. Sweep every page for story-bearing text in the artwork; the detector never sees it.

## Content the agent declines

Violence, weapons, corpses, injury, non-sexual nudity and coarse language are
translated, and are not softened — preserving the original register is the point.

Explicit sexual content is declined. Sexual content involving apparently underage
characters is declined absolutely.

Two properties of this design make that workable rather than fatal:

- **The gap is local.** A declined region is marked in the JSON and the rest of the
  page renders normally.
- **Comprehension survives.** Reading a work that contains such scenes in order to
  understand its plot and characters is separable from translating those scenes.
  This was verified over a 39-page span in which roughly a fifth of pages were
  declined: the resulting plot and character summary was complete and correct,
  including the arc of a character whose scenes were among those declined.

This is a property of using an agent as the translator, not a limitation of the
pipeline. Choosing a work for this workflow is choosing a translator.

Intended to be publishable. That constrains what may be copied.

| transformers | Apache-2.0 | dependency |
| manga-ocr | Apache-2.0 | **not needed** — weights used directly |
| pythainlp, opencv | permissive | dependency |
| skia-python, uharfbuzz | permissive | **not needed** — see rendering below |
| ultralytics (YOLO) | **AGPL-3.0** | **excluded** |
| 2005_iannnnnJPG (font) | free for commercial use | bundled with attribution |

The `manga_ocr` package turned out not to be worth taking either. It is a thin
wrapper whose tokenizer wants mecab and a fast-tokenizer conversion that recent
transformers will not perform without further dependencies — and none of that is
needed to decode, because the vocabulary is one character per line with no word
pieces. Reading `kha-white/manga-ocr-base` (Apache-2.0) through `transformers`
directly is a lookup and a join, and adds no package at all.

`ultralytics` is excluded entirely. Its only use upstream is a single import in the
model manager; detection quality in testing was better without it. Removing it keeps
the whole tree permissively licensed.

Detection uses RT-DETR through `transformers`, with weights from
`ogkalu/comic-text-and-bubble-detector`, which the model card states is Apache-2.0.
The repository references the weights rather than vendoring them regardless: an
Apache-2.0 codebase would not by itself make them redistributable, and they are
170 MB of something this project did not train.

## Copied from upstream

Code is copied into this repository rather than imported. The functions needed are
internal ones with no stability guarantee, so a dependency would break on any
upstream refactor; and the pipeline is being restructured around a different unit of
work, so the parts that are kept diverge immediately.

Copied by role:

- text layout — the line breaker, which is a Knuth-Plass style dynamic program
  with a penalty for a continuation line that starts with a short Thai token

Attribution and the upstream Apache-2.0 notice are retained in `NOTICE`.

Cleaning could not be copied at all. The upstream cleaner is built around a
segmentation mask supplied per bubble by either SAM or a YOLO model; excluding
`ultralytics` took the YOLO one with it, and RT-DETR returns boxes. Rather than
add a segmentation model back for the sake of a mask, `clean` recovers the
interior from the artwork: inside a detected bubble box, it is the paper the
outline encloses, found as a connected component and hole-filled to take in the
lettering. Over the twenty pages of chapter 3 this reproduced every one of the
212 in-bubble regions, and no bubble leaked into the artwork around it.

Free-floating text has no outline and so no interior to find. It is painted out
as a plain white rectangle, which is invisible on a page margin and a white
patch over artwork. Nothing better is available without inpainting, and the
model upstream uses for that is a diffusion model of tens of gigabytes under a
non-commercial licence, which this project cannot take.

Shaping and drawing were not copied either, and neither was the machinery for
them. Thai marks stack above and below the base letter, and in a font that gives
them zero advance — every Thai comic face does — Pillow's own layout puts them
where they belong. `skia-python` and `uharfbuzz` are for the fonts that position
marks through GPOS instead, and nothing here uses one. A font that did would draw
wrongly rather than fail, so a new font is checked before it is trusted.

Three things were worth taking, and taking rather than approximating.

The safe area: a rectangle grown from the centre of the bubble's interior out to
its outline by ray-casting, on a mask already pulled in by a padding. Where that
centre falls in a constriction — less than seven tenths of the deepest point —
it is in the waist between two conjoined lobes, and the anchor moves to the pole
of inaccessibility instead. Conjoined bubbles are common enough on these pages
that this case is not an edge case.

The sizing: binary search within a narrow band, quoted for a one-megapixel page
and scaled by the square root of the actual area so one setting holds across
scan resolutions. The band being narrow is the whole point — most bubbles reach
the top of it and land together, and one that cannot hold its line cannot fall
far. Several attempts at deriving a size per bubble came before this, including
one that estimated what the Japanese had been lettered at; all of them let the
shape of a box decide the size, and a page lettered that way shouts and whispers
by accident.

The collision test: a laid-out block is checked corner by corner against the
mask, not against the rectangle. The rectangle is the full extent of each axis,
so its corners lie outside the curve and a block filling its width collides
there. Narrowing the column and laying out again is what turns two long lines
into a stack that sits inside the oval.

Where the column stops narrowing is the one place this departs from upstream,
and it is a fact about Thai rather than about code. Thai is written
horizontally, but Thai lettering in manga is set to the bubble and not to the
line: a stack of short lines, which Thai readers have read for as long as manga
has been translated into Thai. Upstream stops at the first width that does not
collide, which keeps the widest and shortest block that is merely legal. Here
the narrowing continues and the layout kept is the one that stands tallest.

The line breaker. Filling each line greedily packs it to
the edge and leaves the last nearly empty, which in a bubble this narrow reads as
a mistake; minimising the sum of slack cubed spreads the words evenly. The Thai
part of it is a penalty on a continuation line that begins with a short token,
which is what a break inside a compound leaves behind. With it in place the
choice of segmenter stopped mattering: `newmm` splits บอกว่า as บอ|กว่า, and the
penalty makes the line breaker decline that break anyway.

Two further components originally listed here turned out not to be worth copying
once `ultralytics` was gone. The RT-DETR adapter exists to present the detector
behind ultralytics' `Results` interface, and with no YOLO left to match it is a
shim onto nothing. The model manager is a registry over seven models, six of
them YOLO; for one model, `from_pretrained` already downloads and caches. Both
were replaced by the twenty lines in `manga_honyaku/detect.py` that call
`transformers` directly.

### Apple Silicon

RT-DETR must run on CPU on Apple Silicon; on the MPS backend it fails on a float64
operation. Upstream swallows that exception, so detection silently produces nothing
and conjoined bubbles come out merged and blank. Mixing device placements between
the primary and secondary detectors then segfaults on tensor concatenation. The
device must be pinned once and derived consistently at every call site.

## Open questions

- Free-floating text boxes are cropped tight and sometimes clip the first
  characters, because there is no bubble outline for the model to anchor to. Boxes
  in that placement need expansion before OCR; the margin is not yet determined. For
  erasing, the answer turned out to be no margin at all — the chapter title's box
  ends on the very row where the panel rule begins, so any margin cuts the rule.
- Whether the agent should re-read every `source` or only the ones that look wrong.
  manga-ocr runs inside `prepare` and fills all of them; over chapter 3 it was right
  where the agent, reading a downscaled contact sheet, was wrong twice. Its weak spot
  is free-floating text, whose boxes are cropped tight: it misread the chapter title
  in three places. In-bubble text it read exactly.
- Rendering of `title` regions — chapter headings are typeset, not lettered, and
  probably should not reuse the dialogue font pipeline.
- `words.txt` feeds the line breaker. Anything transliterated and not recorded there
  will be broken across lines as if it were several words; anything recorded there
  that is really several words becomes a floor on its bubble's size.
- Whether `out/` should also emit a sidecar that an existing manga reader can
  overlay, as an alternative to rendering into the artwork.
